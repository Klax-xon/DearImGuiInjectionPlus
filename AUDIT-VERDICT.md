## 1. Executive Release Verdict

### **VERDICT: CONDITIONAL PASS (Production-Ready for v1.0.0 with Minor Non-Blocking Errata)**

Following a forensic line-by-line inspection of `DearImGuiInjectionPlus/`, `RendererFinder/`, and `TestPlugin/`, **all five Critical defects (`MEM-01`, `MEM-02`, `TH-01`, `TH-02`, `LC-01`) and all Major stability/security hazards (`SEC-01`, `SEC-02`, `INP-01`–`INP-04`, `DXH-01`–`DXH-09`, `LC-02`–`LC-05`, `TH-05`, `TH-06`) documented in `PROJECT-ANALYSIS.md` have been resolved.**

Specifically:
1. **D3D11 Backbuffer Pinning Eliminated (`MEM-01`)**: [`ImGuiDX11Impl.StateBackup`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX11Impl.cs#L556-L667) is now a deterministic `IDisposable` container invoked *before* binding the overlay's transient RTV and disposed immediately after state restoration, releasing every `AddRef`'d pipeline interface and allowing `IDXGISwapChain::ResizeBuffers` to succeed unconditionally.
2. **D3D12 SwapChain Over-Release & `Process.Kill()` Eliminated (`MEM-02`, `LC-01`)**: Borrowed swapchain pointers are now properly reference-counted via `Marshal.AddRef` ([`ImGuiDX12.cs#L55-L56`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12.cs#L55-L56)) or guarded via `GC.SuppressFinalize`, and the destructive `Process.GetCurrentProcess().Kill()` hack in `OnDestroy` has been completely removed.
3. **Quiescent Teardown & GPU Synchronization (`TH-01`, `LC-02`, `DXH-05`)**: [`FrameGate`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/RendererFinder/FrameGate.cs#L6-L35) enforces lock-free entry/exit counting around `Present`/`Present1` callbacks and drains in-flight frames during [`DearImGuiInjectionPlusBaseUnityPlugin.OnDestroy`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/BepInEx/DearImGuiInjectionPlusBaseUnityPlugin.cs#L211-L256) *before* disabling hooks, unsubclassing the window, flushing the GPU (`_deviceContext.Flush()` / `WaitForGpuIdle()`), and destroying the native ImGui context.
4. **Strict ImGui Thread Isolation (`TH-02`)**: Cross-thread `ImGuiIO` mutations from the Win32 message pump have been replaced with a lock-free `ConcurrentQueue<InputEvent>` ([`ImGuiWin32Impl.cs#L19`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiWin32Impl.cs#L19), [`InputEvent.cs`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/InputEvent.cs)) drained exclusively on the `Present` thread.
5. **Win32 Unicode Subclassing & Heap Safety (`INP-01`, `INP-03`, `SEC-01`, `SEC-02`)**: Window interception now uses `Comctl32.SetWindowSubclass` / `RemoveWindowSubclass` ([`Comctl32.cs`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Windows/Comctl32.cs)) marshaled to the window-owning thread, preserving native Unicode window status, fixing the `MultiByteToWideChar` buffer allocation in [`ImGuiWin32Impl.cs#L726-L739`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiWin32Impl.cs#L726-L739), and freeing unmanaged `IniFilename` strings strictly *after* `ImGui.DestroyContext`.

The **Conditional Pass** designation reflects a small set of newly identified edge cases (detailed in [Section 3](#3-residual-risks--edge-cases-discovered-in-final-audit)), most notably an un-`AddRef`'d `ID3D12CommandQueue` pointer on the secondary `ExecuteCommandLists` fallback path (`RR-01`) and swapchain recreation rejection on the same `HWND` (`RR-02`). None of these block normal D3D11 or primary-path D3D12 operation, and they can be patched either prior to tagging `v1.0.0` or in `v1.0.1`.

## 3. Residual Risks & Edge Cases Discovered in Final Audit

During independent forensic inspection of the updated codebase, the following subtle defects and edge cases were identified. None affect standard D3D11 or primary D3D12 (`SwapChain::GetDevice` / `QI`) execution, but they should be tracked for remediation.

### `RR-01` (Medium) — Missing `Marshal.AddRef` on Fallback D3D12 Command Queue Capture
- **Location:** [`DX12Renderer.cs#L236-L260`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/RendererFinder/Renderers/DX12Renderer.cs#L236-L260), [`DX12Renderer.cs#L382-L384`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/RendererFinder/Renderers/DX12Renderer.cs#L382-L384), [`ImGuiDX12.cs#L77-L87`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12.cs#L77-L87), [`ImGuiDX12.cs#L270-L282`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12.cs#L270-L282)
- **Root Cause:** When `RendererFinder.QueryCommandQueueFromSwapChain` succeeds (the primary path), `getDevice`/`qi` increments the COM refcount on the returned `commandQueuePtr`, balancing `_commandQueue = new CommandQueue(queuePtr)` and its later `_commandQueue?.Dispose()` in `InvalidateDevice()`. However, if `QueryCommandQueueFromSwapChain` fails and the fallback `ExecuteCommandLists` hook is used, `CommandQueueExecuteCommandListHook` stores the borrowed `self` pointer into `_lastDirectQueueOnCurrentThread` / `_candidateCommandQueue` **without calling `Marshal.AddRef(self)`**, and `GetOrBindQueueForPresent` copies it into `CapturedCommandQueue`. `ImGuiDX12.Init` (or `ImGuiDX12.OnPresent`) then wraps `CapturedCommandQueue` in `new CommandQueue(queuePtr)` without `Marshal.AddRef`, and `ImGuiDX12.InvalidateDevice()` calls `_commandQueue?.Dispose()`, over-releasing the game's `ID3D12CommandQueue` by 1 on shutdown or device reset. (Note: `ImGuiDX12.RetrieveCommandQueue` at [`ImGuiDX12.cs#L204`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12.cs#L204) does call `Marshal.AddRef`, but `RetrieveCommandQueue` is only subscribed *after* `GetOrBindQueueForPresent` has already populated `CapturedCommandQueue`.)
- **Mitigation:** Call `Marshal.AddRef` inside `DX12Renderer.GetOrBindQueueForPresent` when promoting a candidate pointer into `CapturedCommandQueue`, or always call `Marshal.AddRef(queuePtr)` before `new CommandQueue(queuePtr)` while releasing `CapturedCommandQueue` in `DX12Renderer.Dispose()`.

### `RR-02` (Medium) — SwapChain Recreation on the Same `HWND` Without Device Removal Drops Overlay
- **Location:** [`ImGuiDX11.cs#L202-L209`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX11.cs#L202-L209), [`ImGuiDX12.cs#L230-L237`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12.cs#L230-L237), [`ImGuiDX12.cs#L477-L478`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12.cs#L477-L478)
- **Root Cause:** After `IsTargetWindowHandle(windowHandle)` confirms that `swapChain` belongs to the game's main `_windowHandle`, both backends check `else if (swapChain.NativePointer != _currentSwapChainPtr) return;`. Because `_currentSwapChainPtr` is only cleared in `InvalidateDevice()` (which triggers on `DeviceRemovedReason.Failure`), if a game recreates its `IDXGISwapChain` on the **same `HWND` and healthy device** (e.g., certain fullscreen mode transitions or HDR swapchain recreation), the new swapchain pointer is permanently ignored and the overlay stops rendering.
- **Mitigation:** When `IsTargetWindowHandle(windowHandle)` is `true` and `swapChain.NativePointer != _currentSwapChainPtr`, verify whether the new swapchain's device matches `_device.NativePointer` (updating `_currentSwapChainPtr = swapChain.NativePointer`) or call `InvalidateDevice()` so the backend rebinds to the new swapchain on the target window.

### `RR-03` (Low) — `ImGuiDX12Impl` UserCallback `-1` (`ImDrawCallback_ResetRenderState`) Order Bug
- **Location:** [`ImGuiDX12Impl.cs#L273-L283`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12Impl.cs#L273-L283)
- **Root Cause:** In `ImGuiDX12Impl.RenderDrawBuffers`, `Marshal.GetDelegateForFunctionPointer<ImDrawUserCallBack>(pcmd.UserCallback)` is called at line 275 *before* checking `if (pcmd.UserCallback == new IntPtr(-1))` at line 279 (unlike `ImGuiDX11Impl.cs#L360-L372` which checks `new IntPtr(-1)` first and caches delegates in `_userCallbackCache`). If a consumer draw list uses `ImDrawCallback_ResetRenderState` (`-1`) on D3D12, `GetDelegateForFunctionPointer` will be invoked with `-1` (`0xFFFFFFFFFFFFFFFF`) and throw or fault.
- **Mitigation:** Move the `pcmd.UserCallback == new IntPtr(-1)` check above `Marshal.GetDelegateForFunctionPointer` and mirror `_userCallbackCache` from `ImGuiDX11Impl`.

### `RR-04` (Low) — Stale Viewport/Scissor Count Detection in Reused `StateBackup` Singleton
- **Location:** [`ImGuiDX11Impl.cs#L422-L440`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX11Impl.cs#L422-L440), [`ImGuiDX11Impl.cs#L647-L648`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX11Impl.cs#L647-L648)
- **Root Cause:** `_stateBackup` is a reused singleton whose `ScissorRects` and `Viewports` arrays (length 16) are passed to `ctx.Rasterizer.GetScissorRectangles` / `GetViewports`. D3D11 `RSGetViewports` / `RSGetScissorRects` only populates the first $N$ active elements and does not zero trailing slots. Because `StateBackup.Dispose()` resets `ScissorRectsCount = 0` and `ViewportsCount = 0` without clearing `ScissorRects` and `Viewports`, if the game binds 2 viewports on frame $t$ and 1 viewport on frame $t+1$, slot 1 retains its non-zero width/height from frame $t$ and `ViewportsCount` is computed as 2 instead of 1.
- **Mitigation:** Call `Array.Clear(ScissorRects, 0, ScissorRectsCount)` and `Array.Clear(Viewports, 0, ViewportsCount)` inside `StateBackup.Dispose()`.

### `RR-05` (Low) — Cross-Thread `ImGui.GetMouseCursor()` Read on `WM_SETCURSOR` and `RendererFinder.Dispose()` Flag Reset
- **Location:** [`ImGuiWin32Impl.cs#L221-L265`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiWin32Impl.cs#L221-L265), [`ImGuiWin32Impl.cs#L406-L410`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiWin32Impl.cs#L406-L410), [`RendererFinder.cs#L295`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/RendererFinder/RendererFinder.cs#L295)
- **Root Cause:**
  1. `ImGuiWin32Impl.NewFrame()` caches `_lastMouseCursor` on the `Present` thread, but `ImGui_ImplWin32_UpdateMouseCursor()` (called from `WM_SETCURSOR` on the WndProc thread) still calls `ImGui.GetMouseCursor()` and `ImGui.GetIO()` directly instead of reading the cached `_lastMouseCursor` value. If `WM_SETCURSOR` arrives while the render thread is between `ImGui.NewFrame()` (which resets `g.MouseCursor = Arrow`) and widget evaluation, the cursor can briefly flicker to `IDC_ARROW`.
  2. `RendererFinder.Dispose()` sets `IsShuttingDown = false` at [`RendererFinder.cs#L295`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/RendererFinder/RendererFinder.cs#L295) before `OnDestroy` finishes calling `InputManager.Unsubclass()` and `DearImGuiInjectionPlus.Dispose()`.
  3. `ApplyGammaCorrection(true)` in [`ImGuiDX11.cs#L275`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX11.cs#L275) and [`ImGuiDX12.cs#L573`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12.cs#L573) is only called when `IsHdrFormat` is true; calling `DearImGuiTheme.ApplyGammaCorrection(IsHdrFormat(bbFormat))` unconditionally would also restore SDR colors if a user disables HDR mid-session.

### `RR-06` (Informational) — Minor SharpDX `params` Array Allocations in Render Loop
- **Location:** [`ImGuiDX11Impl.cs#L203`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX11Impl.cs#L203), [`ImGuiDX11Impl.cs#L384`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX11Impl.cs#L384), [`ImGuiDX12.cs#L589`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12.cs#L589), [`ImGuiDX12Impl.cs#L299`](file:///d:/BepInEx%20stuff/DearImGuiInjectionPlus/DearImGuiInjectionPlus/Backends/ImGuiDX12Impl.cs#L299)
- **Root Cause:** SharpDX methods `SetScissorRectangles(params RawRectangle[])` and `SetDescriptorHeaps(params DescriptorHeap[])` allocate a 1-element managed array per invocation, and `ImGui_ImplDX11_SetupRenderState` constructs `new VertexBufferBinding()` instead of passing `_vertexBinding`. These are tiny Gen0 allocations (~24–32 bytes per draw list command) with negligible GC impact, though caching a 1-element array or calling the array overload would make the draw loop strictly zero-allocation.
